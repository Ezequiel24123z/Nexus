# Importación OpenAPI — 19 de septiembre de 2026

## Alcance de la entrega

Conectores → Importar OpenAPI ofrece un asistente de dos pasos: archivo local o JSON pegado; revisión, búsqueda, paginación y selección explícita de operaciones. Muestra destino HTTPS, método, nombre resultante, autenticación y motivos de incompatibilidad. Seleccionar operaciones no las ejecuta. No se descargan definiciones ni referencias externas y no se consulta el vault durante la importación.

Esta es una primera implementación acotada, no un importador universal:

- OpenAPI 3.0 y 3.1 en JSON. Máximo 2 MB y 500 operaciones por documento; no limita el número acumulado de conectores.
- GET, POST, PUT, PATCH y DELETE; parámetros simples de ruta/consulta y cuerpo `application/json`.
- Acceso público o una alternativa de autenticación Bearer. Se conserva una referencia `CONNECTOR_`, nunca el valor de la clave. Las exigencias múltiples de autenticación no se reducen silenciosamente a una sola.
- Referencias locales, parámetros heredados con sustituciones por operación y prioridad de servidores operación/ruta/documento. El usuario puede indicar un servidor alternativo para todo el lote. Sin alternativa, se utiliza el primer servidor efectivo; las variables necesitan valor por defecto.
- Esquemas simples con tipos, propiedades, campos requeridos, listas, enumeraciones, `nullable` de 3.0 y `additionalProperties` booleano. Los formatos son anotaciones: no se valida email/fecha. Composiciones, restricciones adicionales, esquemas recursivos, multipart, YAML, OAuth y autenticación API-key aparecen como no compatibles, sin crear una definición parcial.

Los detalles de herencia, seguridad y serialización se contrastaron con la [especificación oficial OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html). No se ha copiado código de implementaciones externas ni añadido dependencias.

## Persistencia y ejecución

Los nombres combinan prefijo, identificador de operación y un sufijo estable derivado de método/ruta. Al confirmar se vuelve a analizar y validar todo el lote. Si un nombre ya existe, no se sobrescribe: cambia el prefijo o conserva la definición actual. La selección no puede incluir duplicados ni operaciones incompatibles.

El lote se guarda con la persistencia atómica existente. Un fallo de guardado restaura la colección anterior en memoria y no publica un evento de éxito. Los conectores quedan en el estado principal y están incluidos en sus exportaciones; no se importa ni modifica ningún secreto.

Los agentes usan `list_connectors` para metadatos paginados y `get_connector` para cargar un único contrato antes de `invoke_connector`. La importación no amplía la lista de herramientas con un esquema por cada operación. La nueva herramienta de consulta sí añade un coste fijo; esta ronda no mide ahorro real de facturación ni cache hit.

Ejemplo de entrada para un conector importado:

```json
{"path":{"id":"item-123"},"query":{"limit":20},"body":{"name":"Nuevo nombre"}}
```

Sólo deben incluirse los grupos que admita esa operación. Ruta y consulta se codifican por separado; se comprueban tipos, valores requeridos y propiedades desconocidas antes de enviar. El contrato es visible desde la definición. La ruta y el método importados no se editan de forma aislada para evitar desajustarlos; reimporta con otro prefijo si necesitas otro endpoint.

Los conectores manuales anteriores conservan su entrada plana. Las llamadas mantienen las reglas de aprobación, diario e idempotencia existentes. El importador no atribuye soporte `Idempotency-Key` a una API sin que se configure expresamente.

## Correcciones adicionales

- Las respuestas HTTP sin cuerpo, como 204, ya no intentan leer un stream inexistente.
- La lectura REST conserva los caracteres UTF-8 que llegan repartidos entre fragmentos.
- Los catálogos del agente ya no envían contratos completos en cada página: se consultan por nombre.

## Límites operativos y siguientes pasos

El análisis JSON y el guardado son síncronos en el proceso principal, acotados por documento. No se ha medido la fluidez con todos los documentos extremos ni el arranque con miles de contratos físicos. Las descripciones proceden de una especificación no confiable: son datos, no instrucciones que deban prevalecer sobre la tarea del usuario. No introducir credenciales en descripciones, URLs o ejemplos.

Siguientes ampliaciones útiles: editor guiado de argumentos y prueba explícita de una operación; importación de paquetes de skills sin ejecución automática; más serializaciones y autenticación con selección explícita; mover análisis/I/O fuera del proceso principal si las mediciones lo justifican.

No se genera instalador ni se reinicia la sesión del usuario. Las pruebas utilizan datos temporales y respuestas simuladas, sin control de escritorio ni llamadas de inferencia de pago.
